# AI 加速卡单卡对比 · 大模型算力估算

一个零依赖的单文件网页 [index.html](index.html)，做两件事：把数据中心级 GPU / DCU 单卡的关键参数放在同一张桌子上横向对比，再按显存估算口径回答“跑这个模型要多少张卡”。

数据截至 2026-10，全部规格逐条核对厂商官网，未公开的留空不估算。

---

## 一、它回答的两个问题

**问题一：这些卡到底有什么差别？**
纸面参数分散在各家官网、白皮书和发布会 PPT 里，同名卡的 PCIe 版与 OAM 版算力不同、风冷与液冷档位不同，很多小型号根本没人把它们并列放过。本页面把 37 张数据中心级单卡拉到同一口径下：同一列可比较，同一行看全貌，最多选 6 张进入差异对比表。

**问题二：我这套模型要吃掉多少算力？**
选一个 2026 年现役的主流大模型，指定训练还是推理、权重精度、序列长度与并发，页面按显存构成逐项拆开算出总需求，再除以单卡可用显存，给出需要多少张卡、几台整机，并同屏列出这一需求在 20 张预设主流卡（以及你额外勾选的卡）上分别要多少张。

## 二、单卡参数对比

### 收录口径

- **只收数据中心级单卡**。消费级显卡、图形工作站卡、整机/服务器方案不在范围内；需要区分的是“单卡”，不是“系统”。
- **有小型号就拆开**。只要算力或显存不同，各占一行，不合并、不取中间值。已按此规则拆出的：
  - H100 SXM5 与 H100 PCIe（989.5 vs 756 TFLOPS）
  - Gaudi 3 的 OAM 版 HL-325L 与 PCIe 版 HL-338（900W vs 600W）
  - Atlas 300I A2 的 64GB 与 32GB 两档（带宽分别为 1.6 与 0.8 TB/s）
  - Atlas 350 与 Atlas 150（同一颗 Ascend 950PR，仅 HBM 容量 112 vs 84 GB）
  - MI350X（风冷）、MI355X（液冷）、MI350P（PCIe）三档分别录入
- **未公布就留空**。昇腾 910C、思元 590/690 等官网无单卡规格页的条目，来源标注为媒体口径；厂商一个数都没给的格子显示 `—`，绝不用竞品数值或同代产品去“推算补齐”。
- **算力一律稠密（Dense）口径**。官方只公布稀疏值的，按 1/2 折算后录入并标 `†`；按同代产品规格回推的同样标 `†`（如真武 810E 的 FP16 120 TFLOPS）。

### 对比维度

每张卡记录的字段：型号、厂商、架构、发布年份、量产状态（已出货 / 爬坡新品）、形态（SXM、OAM、PCIe 等）、适用场景（训练 / 推理）、显存容量与类型、显存带宽、FP16/BF16 与 FP8、FP4、INT8 四个精度的稠密算力、片间互联方式与带宽、整卡功耗、产品定位、规格备注。

## 三、主流模型训练与推理需要多少算力

### 估算口径

显存算法沿用阿里云 PAI《模型所需显存估算》。选定模型与场景后，页面把显存拆成六项分别计价，逐项列在结果表里：

| 组成 | 计价方式 |
| --- | --- |
| 权重 | 总参数 × 每参数字节（BF16/FP16 为 2，FP8/INT8 为 1，FP4/INT4 为 0.5） |
| 梯度 | 可训练参数 × 2 字节 |
| 优化器状态 | 可训练参数 × 4 字节 × 状态份数（AdamW 为 2 份，SGD+Momentum 为 1 份，SGD 为 0 份） |
| 激活值 | 参与前向的参数量 × 2 字节 × 10%，以 batch/并发 1、序列 2048 为基线，按 并发数 ×（序列长度 ÷ 2048）线性放大 |
| KV Cache | 激活参数 × 2 字节 × 10%，同上随并发与序列长度放大（仅推理场景） |
| 其他 | 固定 2 GB，覆盖框架、驱动上下文与输入缓冲 |

两条针对 MoE 的处理规则：权重按**总参数**计价（专家全部要驻留显存），激活值与 KV Cache 按**激活参数**计价；LoRA / QLoRA 的可训练参数取总参数的 1%。

得到合计需求后，再换算卡数：

```
单卡可用 = 显存容量 × 可用比例（默认 90%，扣除框架占用与碎片）
需要张数 = ⌈合计需求 GB ÷ 单卡可用 GB⌉
需要台数 = ⌈张数 ÷ 整机卡数⌉（可选 8 卡机 / 16 卡机 / 单卡，默认 8 卡机）
```

### 五种场景

| 场景 | 可训练参数 | 权重精度 | 说明 |
| --- | --- | --- | --- |
| 推理部署 | — | 自选 BF16 / FP8 / FP4 | 权重 + 激活 + KV Cache，用并发路数控制规模 |
| 全参微调 | 100% | 固定 BF16/FP16 | 梯度与优化器状态全额计入，是资源消耗上限 |
| LoRA 微调 | 1% | 固定 BF16/FP16 | 基座权重不更新，但仍需驻留 |
| QLoRA（基座 8bit） | 1% | 1 字节 | 基座量化为 INT8/FP8 |
| QLoRA（基座 4bit） | 1% | 0.5 字节 | 基座量化为 INT4/FP4，单卡可跑的最省档位 |

### 结果里的三条自动提示

估算不只给数字，还会把数字撑不住的地方标出来：

- **跨机提示**：所需张数超过整机卡数时，说明需要跨机部署，并提醒实际可行性还取决于互联带宽、并行策略与框架适配 —— 显存装得下不等于跑得起来。
- **低精度支持提示**：所选权重精度对应的稠密算力该卡未公布时（例如多数国产卡只公布 BF16 与 INT8），提示低精度权重能否跑满需按软件栈复核，不要默认 FP8 卡一定有 FP8 性能。
- **供货提示**：状态为“爬坡”的卡（Rubin VR200、MI450/MI455X、真武 V900）提示尚未量产出货。

### 这些数字不是什么

结果是**理论下界**，不包含并行切分带来的权重与优化器副本、激活检查点重算、通信缓冲区、专家并行的负载不均，也不评估吞吐、延迟、首 token 时间与单位 token 成本。真正拍板选型前，要用自己的模型和数据做一次小规模实测；这里的数字用于框定量级、排除明显不可行的方案。

## 四、数据来源与核查方式

37 张卡的规格逐条在厂商自己的产品页核对，未使用第三方汇总站的数据：

- NVIDIA 产品页与白皮书（Hopper / Blackwell / Ada 各卡规格表）
- AMD Instinct 产品页（MI300X、MI325X、MI350X、MI355X、MI350P、MI450 系列）
- Intel Gaudi 3 产品简介（HL-325L OAM 与 HL-338 PCIe 两种板型）
- 华为昇腾 `hiascend.com` 硬件页的加速卡分档（Atlas 300T A2、300I A2、300I Duo、300I Pro、Atlas 150、Atlas 350）
- 摩尔线程、壁仞、天数智能官网产品页

模型参数量以厂商公开发布口径为准，页面内逐条标注出处：能在官方渠道（如阿里云百炼模型列表、Kimi 开放平台、模型发布说明）查到的标 `官方 ·`，只有媒体报道的标 `媒体口径 ·`。

三条不可让的规矩：

1. 官方只公布稀疏（Sparsity）口径的，折半换算为稠密并标 `†`；按同代产品回推的数值同样标 `†`（真武 810E 的 FP16 120 TFLOPS 即按 M890 回推，非官方口径）。
2. 厂商未公布的格子一律留 `—`，不用竞品数值、不用“行业平均水平”补齐。
3. 同一代产品不同分档只要算力或显存不同就各占一行，不取中间值。

**已知未拆分**：壁仞、天数、海光、昆仑芯、寒武纪、沐曦存在媒体提到的多个子型号或液冷变体，但官网没有对应单卡规格页，为避免把传闻写进参数表，只收录能核对到规格的版本，其子型号与散热变体不做拆分；Intel Gaudi 3 的 1200W 液冷档与 NVIDIA H100/H200 NVL 变体同理待补。
